# RAG 系统与评估

Retrieval-Augmented Generation 将外部知识检索与语言模型生成结合。典型流程包括文档解析、文本清洗、切块、向量或关键词索引、召回、重排、上下文拼接和答案生成。RAG 更适合注入可更新的事实知识，而微调通常更适合改变模型行为、输出风格或掌握特定任务格式。

Chunk 太小时，单个片段可能缺少回答问题所需的完整上下文；Chunk 太大时，向量表示会混合多个主题，检索精度下降，同时占用更多上下文窗口。Overlap 可以减少信息在切分边界处丢失，但重叠过大会增加索引体积和重复召回。

BM25 是基于词项匹配的稀疏检索方法。它使用逆文档频率强调稀有词，通过 k1 控制词频饱和，并通过 b 调整文档长度归一化。BM25 对专有名词和精确关键词很有效，但处理同义表达的能力有限。

Dense Retrieval 使用神经网络把问题与文档编码成向量，根据向量相似度召回语义相关内容。它能处理部分同义表达，但可能忽略精确关键词。Hybrid Retrieval 将稀疏与稠密检索结合，Reranker 再使用更强模型对候选片段重新排序。

检索和生成应分别评估。Recall@K 衡量前 K 个结果覆盖了多少相关来源；Hit Rate@K 只判断是否至少命中一个相关来源；MRR 关注第一个相关结果出现的位置。生成阶段还需评估答案正确性、忠实度、引用准确性与拒答能力。

RAG 失败可分为两类：检索失败，即正确资料没有进入上下文；生成失败，即正确资料已经被召回，但模型仍然回答错误或添加了资料中不存在的内容。保留逐题检索结果和失败案例，才能定位应该优化切块、召回、重排、提示词还是生成模型。
