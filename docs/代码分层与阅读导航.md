## 1. 目录与依赖

重构前的 `domainrag/` 是扁平包。三个入口、检索器、模型适配器、知识工具、Agent 循环、数据契约和评测均处在同一级。

```text
domainrag/                          重构前
├── cli.py, tools.py, agent.py, holdout.py
├── bm25.py, embedding.py, hybrid.py, reranker.py, retriever.py
├── generator.py, answer_evaluation.py
├── models.py, text.py, chunking.py, io.py
└── evidence.py, evaluation.py, failures.py, frozen.py

domainrag/                          重构后
├── bootstrap.py
├── domain/
│   ├── __init__.py                统一导出核心契约与 Evidence
│   └── protocols.py              Retriever、ChatModel、评测接口、Schema
├── application/
│   ├── knowledge_service.py      KnowledgeTools、ToolSession
│   └── evaluation_service.py     答案评测与检索评测入口
├── infrastructure/
│   ├── retrievers/               bm25、embedding、hybrid、reranker
│   ├── llm/                      generator、answer_judge、tool_model
│   └── storage/trace.py          独占创建与写入 JSONL
├── workflows/
│   ├── native_agent.py           原生工具循环与共用的步骤逻辑
│   ├── langgraph_agent.py        StateGraph 节点与路由
│   └── langgraph_state.py        图状态与消息追加规则
├── cli.py, tools.py, agent.py, langgraph_cli.py, holdout.py
├── 旧路径兼容导出                 retriever、检索器、generator、answer_evaluation
└── 原路径冻结源码与校验           models、evidence、evaluation、chunking、text、io、failures、frozen
```

`cli.py`、`holdout.py` 和 `KnowledgeTools.from_config()` 通过 `bootstrap` 装配检索链。装配顺序为读配置 → 校验冻结清单 → 加载文档 → 切块 → 创建检索器及可选重排器。`build_retriever_from_documents()` 只处理调用方提供的快照。检索索引、Evidence 评测或知识补读可以共享这批文档。

应用服务通过 `Retriever` 接收检索能力。原生工作流通过 `ChatModel` 接收模型能力，并使用 `KnowledgeTools` 与 `ToolSession` 执行工具。HTTP 适配器依赖领域协议，JSONL 写入由存储适配器负责，会话仍负责事件语义。只有兼容工厂 `KnowledgeTools.from_config()` 局部导入 bootstrap；直接注入依赖的构造路径与模块导入无需装配。工具与工作流均可独立于 CLI 导入。

旧路径显式导出同一个类或函数，适用于现有调用与普通导入。Mock 应拦截运行时使用的名字，例如 `domainrag.bootstrap.verify_frozen_dataset` 和 `domainrag.infrastructure.llm.tool_model.urlopen`。V2 冻结清单直接校验七个源码路径，相关实现保留原位并由领域层或评测服务复用。运行指纹现在递归记录嵌套源码，已有报告依然使用各自生成时的指纹。

原生与 LangGraph 工作流都通过入口接收模型、知识服务和预算，每次调用创建一个 `ToolSession`。StateGraph 管理节点间的数据流，节点与原生循环共用模型响应解析、工具观察、引用校验和终态封装。[LangGraph V1 数据流与复习](项目数据流与面试复习.md#8-langgraph-agent-v1)

## 2. 先认识这一条主线

```text
Markdown / TXT 文档
  → io.py：Document
  → text.py + chunking.py：规范化和重叠切块，得到 Chunk
  → BM25Retriever + EmbeddingRetriever（BGE）
  → HybridRetriever：RRF 按排名融合候选
  → CrossEncoderReranker：问题与候选成对评分，得到最终 Top-K
      ├─ 固定 RAG：把问题和证据拼入 Prompt → 模型回答
      └─ Agent：模型选择检索/补读 → 工具执行 → 结果回传 → 模型继续或回答
```

固定 RAG 在模型生成前运行检索链。Agent 在模型提出 `search_knowledge` 时运行同一检索链；`read_document` 则按已知来源读取原文窗口。Agent 不要求每次都补读，也不要求检索次数固定。

## 4. 直接用完整链路配置

读 [configs/hybrid_reranker.json](../configs/hybrid_reranker.json)。其中：

- `retriever: hybrid`：并行概念上的双路召回；当前代码依次调用 BM25 和 BGE 检索器。
- `embedding.model`：`BAAI/bge-small-zh-v1.5`。
- `hybrid.candidate_k: 10`、`rrf_k: 60`：双路候选与融合参数。
- `reranker.enabled: true`、`candidate_k: 10`：将融合候选交给 Cross-Encoder。
- `top_k: 3`：重排后最终返回的证据数量。

四个配置便于逐层比较：`bm25_baseline.json → embedding_baseline.json → hybrid_rrf.json → hybrid_reranker.json`。想看完整主线时，选择最后一个。

## 5. 终端入口

在项目根目录、Python 3.10+ 环境中执行。BM25 基础流程只用标准库。BGE 和 ONNX 重排使用可选依赖与模型权重，架构重构使用离线替身验证装配。

完整检索链所需依赖按需安装：

```powershell
python -m pip install -e ".[reranker]"
```

只看完整检索链返回的片段：

```powershell
python -m domainrag.cli query --config configs/hybrid_reranker.json --question "为什么注意力分数要除以根号维度？"
```

固定 RAG：

```powershell
python -m domainrag.cli answer --config configs/hybrid_reranker.json --question "为什么注意力分数要除以根号维度？" --provider deepseek
```

原生 Agent：

```powershell
python -m domainrag.agent --config configs/hybrid_reranker.json --question "为什么注意力分数要除以根号维度？"
```

后两条命令会使用 `DEEPSEEK_API_KEY` 调用真实模型，并发送问题、提示词和实际取得的资料；本次没有执行。Agent 会在预算内进行多次模型/工具调用。普通问答不调用 Judge。

没有可选模型依赖时，可先用 `configs/bm25_baseline.json` 运行 `query` 理解数据流，再阅读双路召回和重排实现。

图版 Agent 的 extra、独立入口和离线验证命令见 [本地运行指南](本地运行指南.md#langgraph-agent-v1)。
