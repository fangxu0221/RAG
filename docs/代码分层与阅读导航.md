## 1. 先认识这一条主线

```text
Markdown / TXT 文档
  → io.py：Document
  → text.py + chunking.py：规范化和重叠切块，得到 Chunk
  → BM25Retriever + EmbeddingRetriever（BGE）
  → HybridRetriever：RRF 按排名融合候选
  → CrossEncoderReranker：问题与候选成对评分，得到最终 Top-K
      ├─ 固定 RAG：把问题和证据拼入 Prompt → 模型回答
      └─ Agent：模型选择检索/补读 → 工具执行 → 结果回传 → 模型继续或回答
```

固定 RAG 在模型生成前运行检索链。Agent 在模型提出 `search_knowledge` 时运行同一检索链；`read_document` 则按已知来源读取原文窗口。Agent 不要求每次都补读，也不要求检索次数固定。

## 3. 直接用完整链路配置

读 [configs/hybrid_reranker.json](../configs/hybrid_reranker.json)。其中：

- `retriever: hybrid`：并行概念上的双路召回；当前代码依次调用 BM25 和 BGE 检索器。
- `embedding.model`：`BAAI/bge-small-zh-v1.5`。
- `hybrid.candidate_k: 10`、`rrf_k: 60`：双路候选与融合参数。
- `reranker.enabled: true`、`candidate_k: 10`：将融合候选交给 Cross-Encoder。
- `top_k: 3`：重排后最终返回的证据数量。

四个配置便于逐层比较：`bm25_baseline.json → embedding_baseline.json → hybrid_rrf.json → hybrid_reranker.json`。想看完整主线时，选择最后一个。

## 4. 终端入口

在项目根目录、Python 3.10+ 环境中执行。BM25 基础流程只用标准库；BGE 和 ONNX 重排需要可选依赖与模型权重。现有验证环境没有安装这些重型可选依赖，本次没有下载权重或重跑真实推理。

完整检索链所需依赖按需安装：

```powershell
python -m pip install -e ".[reranker]"
```

只看完整检索链返回的片段：

```powershell
python -m domainrag.cli query --config configs/hybrid_reranker.json --question "为什么注意力分数要除以根号维度？"
```

固定 RAG：

```powershell
python -m domainrag.cli answer --config configs/hybrid_reranker.json --question "为什么注意力分数要除以根号维度？" --provider deepseek
```

原生 Agent：

```powershell
python -m domainrag.agent --config configs/hybrid_reranker.json --question "为什么注意力分数要除以根号维度？"
```

后两条命令会使用 `DEEPSEEK_API_KEY` 调用真实模型，并发送问题、提示词和实际取得的资料；本次没有执行。Agent 会在预算内进行多次模型/工具调用。普通问答不调用 Judge。

没有可选模型依赖时，可先用 `configs/bm25_baseline.json` 运行 `query` 理解数据流，再阅读双路召回和重排实现。
