## 候选核验与冻结

[自动审核脚本](../scripts/railpolicy_v2_auto.py)根据上轮内容审核确定的引文锚点，遍历 9 份 Markdown 中的 197 个单位。每条候选核对 `source`、`unit_id`、原文精确匹配、规范化位置和能覆盖它的 Chunk。锚点搜索以已知漏标为范围，覆盖所有文件和单位，无法保证穷尽同义表达。

DeepSeek `deepseek-flash` 和 `deepseek-v4-pro` 分别盲审同一批候选。输入只含题目、标准答案、组内要点、原文及单位上下文。两次请求均完成，各返回 26 条判定。审核提示、请求哈希、返回模型、服务指纹、使用量及理由可核对。[DeepSeek API 模型说明](https://api-docs.deepseek.com/quick_start/pricing) · [JSON 输出协议](https://api-docs.deepseek.com/guides/json_mode/)

19 条双审通过，5 条一致拒绝，2 条 `uncertain`。两个审核模型来自同一提供商，审查相互隔离。必要组之间为 AND，同组引文为 OR。一个组包含多个要点时，每个替代引文都必须同时支持组内全部要点，例如 004 的两档费率、006 的时点和运力条件。保持组数可避免在重评分中混入分母变化。
